# TeamBook — блокнот руководителя

Персональный самохостинговый блокнот руководителя для ведения заметок о подчинённых: карточки сотрудников, справочники должностей и отделов, история смены должности и зарплаты, полугодовые записи (цели, предложения, пожелания, комментарии, отзывы коллег) и итоги встреч 1-на-1. Плюс канбан-доска с гантом для задач, личный todo-блокнот в виде матрицы Эйзенхауэра, уведомления-колокольчик и встроенный Telegram-бот.

Данные хранятся локально в SQLite (на вашем сервере) — ничего не уходит наружу. Доступ защищён входом по паролю. Встроена резервная копия: экспорт и восстановление базы через браузер.

## Возможности

**Сотрудники**
- Карточка сотрудника: имя, должность, отдел, зарплата, дата приёма на работу
- История изменений должности и зарплаты по датам (таймлайн)
- Общие заметки о сотруднике (вне привязки к полугодию)
- Кликабельные имена в списке, поиск по имени и фамилии

**Справочники**
- Должности, отделы и теги: создание, переименование, удаление
- Выбор должности/отдела из выпадающего списка при создании и редактировании сотрудника
- Теги — цветные метки сотрудника (например: риск ухода, наставник, зона роста), отображаются в списке и карточке

**Записи по годам**
- Разбивка данных по годам: годы создаются вручную (кнопка «Создать год»), каждый можно и удалить
- Полугодовые записи (I и II полугодие): цели сотрудника, мои предложения, его пожелания, комментарии, отзывы коллег
- Поля полугодий — столбиком сверху вниз

**Встречи и проблемы**
- Встречи 1-на-1: отдельная секция в карточке сотрудника (дата, итоги, правка, удаление)
- **Проблемы в работе** — актуальные задачи: блок в карточке сотрудника и общий список по всем («Проблемы» в меню). Добавляется и из карточки, и из общего списка; отмечается решённой ✔. Счётчик нерешённых — в меню и на дашборде

**Доска (канбан + гант)**
- Канбан-доска со свободными столбцами: создаются/переименовываются/удаляются, **порядок переставляется перетаскиванием** (ручка ⠿)
- Задача добавляется сразу в нужную колонку (форма «+ задача» в каждой колонке), у задачи — описание, **несколько исполнителей**, даты начала и срока (для ганта)
- **Перетаскивание карточек мышью** между колонками; фильтры (поиск, исполнитель, только просроченные, без исполнителя); подсветка просрочки
- **Гант** — календарная сетка по месяцам (Пн–Вс), задачи в ячейках дней
- Архив и корзина доски: отложенные и удалённые задачи отдельными страницами (корзина пурится через 30 дней)
- Счётчик просроченных задач в меню

**Личный todo (матрица Эйзенхауэра)**
- Раздел «Мои задачи»: **бэклог** (точка входа новых задач) + **матрица 2×2 «важно × срочно»** (🔴 Сделать, 🟠 Запланировать, 🟡 Делегировать, 🟢 Удалить)
- Перетаскивание задач между бэклогом и квадрантами мышью; порядок в бэклоге ↑/↓
- У задачи — **срок** (подсветка просрочки + попадает в уведомления) и **тег**; редактирование в модалке
- Поиск и фильтр по тегу
- **Архив** выполненных («Сделано» → в архив), просмотр за любую дату, возврат задачи в бэклог
- Счётчик невыполненных задач в меню и на дашборде
- **Делегирование** задачи прямо в канбан-доску

**Уведомления**
- Колокольчик в шапке: просроченные и ближайшие (+3 дня) задачи канбана и личного todo
- Счётчики-бейджи в меню (Доска, Мои задачи, Проблемы)

**Телеграм-бот (опционально)**
- Встроенный Telegram-бот: сотрудники, записи, проблемы, задачи канбана, личный todo (просмотр/добавление напрямую)
- Быстрые кнопки главного меню; включение и токен — на странице «Настройки»

**Дашборд**
- «Цифры недели»: открытые и просроченные задачи, проблемы, записи за год, задачи личного todo, выполнено сегодня
- Фильтрация сотрудников по отделу и должности; поиск по имени и фамилии

**Резервное копирование**
- Экспорт полной копии базы одним файлом (скачивание через браузер)
- Восстановление из файла через загрузку (с проверкой целостности и авто-бэкапом текущей БД)

**Отчёт (Excel/PDF)**
- Выгрузка по всем сотрудникам за выбранный год: карточка + I/II полугодие (цели, предложения, пожелания, комментарии, отзывы коллег)
- Выгрузка по одному сотруднику с его карточки (плюс отдельный лист «Встречи 1-на-1»)
- Формат на выбор: **Excel (.xlsx)** или **PDF** (кириллица поддерживается)

**Интерфейс**
- Тёмная и светлая темы — переключаются кнопкой ◐ в шапке, выбор запоминается
- Адаптивная вёрстка (компьютер, планшет, телефон)
- Сворачиваемые блоки (спойлеры), состояние запоминается в браузере
- Полностью на русском языке

## Быстрый старт (Docker)

Требуется: **Docker + Docker Compose** (входит в Docker Desktop / Docker Engine).

### Шаг 1 — файл `.env`

Создайте файл `.env` рядом с `docker-compose.yml`:

```bash
# Пароль для входа в приложение (обязательно)
HR_PASSWORD=мой_надёжный_пароль
# Секретный ключ сессий — любая длинная случайная строка
HR_SECRET_KEY=$(openssl rand -hex 24)
```

### Шаг 2 — `docker-compose.yml`

Создайте файл `docker-compose.yml`:

```yaml
services:
  teambook:
    image: ghcr.io/shoonia69/teambook:latest
    container_name: teambook
    restart: unless-stopped
    environment:
      - HR_PASSWORD=${HR_PASSWORD:?задайте HR_PASSWORD в .env}
      - HR_SECRET_KEY=${HR_SECRET_KEY:?задайте HR_SECRET_KEY в .env}
    volumes:
      - teambook_data:/app/data
    ports:
      - "5500:5000"

volumes:
  teambook_data:
```

### Шаг 3 — запуск

```bash
docker compose up -d
```

Приложение поднимется на **http://localhost:5500**. Вход — по паролю из `HR_PASSWORD`.

> ⚠️ Секреты (`HR_PASSWORD`, `HR_SECRET_KEY`) подставляются из `.env`, а не хранятся в самом compose-файле — не коммитьте `.env` в репозиторий.

### Без Compose (просто Docker)

```bash
docker pull ghcr.io/shoonia69/teambook:latest
docker run -d --name teambook \
  -p 5500:5000 \
  -e HR_PASSWORD=мой_пароль \
  -e HR_SECRET_KEY=мой_ключ \
  -v teambook_data:/app/data \
  ghcr.io/shoonia69/teambook:latest
```

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `HR_PASSWORD` | да | Пароль для входа в приложение |
| `HR_SECRET_KEY` | рекомендована | Секретный ключ для подписи сессий |
| `HR_DATA_DIR` | нет | Каталог хранения БД (по умолчанию `/app/data`) |
| `PORT` | нет | Внутренний порт приложения (по умолчанию 5000) |

## Хранение данных и резервная копия

- Все данные — в одном файле SQLite (`/app/data/hr_notes.db`).
- В `docker-compose.yml` объявлен named volume `teambook_data`, поэтому **данные переживают пересоздание контейнера**.
- Из интерфейса: страница «Резервная копия» — скачать БД одним файлом или восстановить из файла.
- Из консоли бэкап — просто скопировать файл: `docker cp teambook:/app/data/hr_notes.db ./`

---

## Перенос на другой сервер

1. Старый сервер: откройте «Резервная копия» → «Скачать копию БД» (или `docker cp`).
2. Новый сервер: тот же `docker-compose.yml` + `.env`.
3. Запустите `docker compose up -d`.
4. Восстановите базу: «Резервная копия» → «Восстановить из файла».

## Разработка (без Docker)

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install --require-hashes -r requirements.lock

export HR_PASSWORD=test
export HR_SECRET_KEY=dev-secret
python app.py                    # http://localhost:5000
```

### Тесты

```bash
python test_app.py        # функциональные тесты
python test_migration.py  # тест миграции старой схемы
python test_repair.py     # тест починки FK-ссылок
```

Новые и постепенно переносимые тесты находятся в `tests/` и запускаются через:

```bash
python -m pytest -q
```

После изменения `requirements.txt` пересоздайте lock-файл закреплённым
`uv 0.12.18`:

```bash
uv pip compile requirements.txt \
  --python-version 3.12 \
  --python-platform linux \
  --no-annotate --no-header --generate-hashes \
  -o requirements.lock
```

CI повторяет эту команду и отклоняет рассинхронизацию исходного файла и lock-файла.

## Структура проекта

```
.
├── app.py                 # Flask-приложение (логика, маршруты, миграции)
├── wsgi.py                # точка входа для gunicorn
├── bot.py                 # супервизор Telegram-бота (держит воркер живым)
├── bot_worker.py          # воркер Telegram-бота (python-telegram-bot)
├── requirements.txt       # прямые зависимости и допустимые диапазоны
├── requirements.lock      # зафиксированные runtime-зависимости
├── Dockerfile
├── entrypoint.sh          # входной скрипт контейнера (бот + gunicorn)
├── docker-compose.yml
├── docker-compose.prod.yml # вариант для production-деплоя
├── .env.example           # шаблон переменных окружения
├── static/style.css       # стили
├── templates/             # HTML-шаблоны
└── test_*.py              # тесты
```
